## 什么时候用
用户要验证改动，或者想知道测试为什么红。只做「跑 + 报告」，不做修。

## 步骤
1. 先跑 `python -m unittest discover -s . -p "test_*.py" -q`。
   没有 unittest 用例时，再试 `python -m pytest -q`；不要一上来就 `-v`。
2. 只读失败用例的 traceback，最多 3 个；不要为了看报错把整个文件读进来。
3. 总结成四行：哪个用例 / 期望什么 / 实际什么 / 最可能的原因。
4. 如果连续两次跑出同样的红，停下来报告，不要换命令瞎试。

## 不要做什么
- 不跑 `pip install`，不装新依赖
- 不改测试来让结果变绿
- 不贴整段 traceback（只贴断言那两行）

## 输出模板
```
测试：5 绿 1 红
- test_mean_empty_should_raise
  期望：抛 ValueError
  实际：返回 0
  原因：mean() 第 6 行把空列表当合法输入
```

## 怎么算做完了
- 说清「几红几绿」
- 每个红都有「期望 / 实际 / 原因」三行，且原因指向具体文件与行号
- 报告里不出现"应该可以了""大概没问题"这类没跑过的判断
