## 什么时候用
任务的信息在外部系统（issue 跟踪器）里，而不是在本地文件里。

## 步骤
1. 调 MCP 工具 `mcp__fixture__get_issue`，参数 `{"number": <编号>}`。
   用户没给编号就用 1；给了多个就逐个读，最多 3 个。
2. 只读返回的标题、正文、标签，不要补全没返回的字段。
3. 总结成四段：问题是什么 / 影响谁 / 复现步骤 / 建议先看哪个文件。
4. 如果 MCP 返回错误，把错误原文贴出来并说明连不上，不要改用浏览器绕。

## 不要做什么
- 不猜 issue 编号，不编造标签
- 不因为一次失败就换工具重试三遍
- 不把 issue 正文整段复述

## 返回字段
只认这五个：`number`、`title`、`state`、`labels`、`body`。
返回值里没有的字段一律当成不存在，不要按经验补全。

## 怎么算做完了
- 四段都有内容，且每段都能在 MCP 返回值里找到依据
- 如果 MCP 报错，报告里要出现原始错误信息，而不是"获取失败"四个字
