## 什么时候用
用户要的是「讲」，不是「改」。只做讲解，不顺手重构、不提 PR 建议。

## 步骤
1. 先 `read` 完整读一遍目标文件，讲之前至少自己读完整——不要只看函数名就开讲。
2. 按「这个文件解决什么问题 → 入口在哪 → 数据怎么流」三段组织，每段不超过 3 句。
3. 讲到具体行为时引用 `文件名:行号`，让听众能自己跳过去看。
4. 听众是新人：术语第一次出现要用一句话解释，不堆缩写。

## 不要做什么
- 不改代码，讲解过程中发现 bug 只在末尾提一句，不展开
- 不复述整段代码（贴出来的行数不超过讲解里引用的那些）
- 不用"显然""很简单"这类词——对新人没有一条路是显然的

## 输出模板
```
stats.py：一个统计小模块
入口：summary(nums)（第 23 行），对一组数返回 n / mean / median
数据流：nums → mean()（第 4 行）→ median()（第 13 行）→ dict
坑：mean() 第 5-6 行对空列表返回 0，与 median() 抛 ValueError 的策略不一致
```

## 怎么算做完了
- 三段结构齐全，且每段都能落到具体行号
- 出现的每个术语都有一次性解释
- 讲解长度不超过 15 行——超了说明在背代码，不是在讲代码
